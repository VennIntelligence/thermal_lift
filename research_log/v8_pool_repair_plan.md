# V8 池修复计划：三层验证阶梯（2026-07-09 夜，owner 授权自治执行）

## 问题（背景：ACL-063 → 065 → 066 → 067）

v7 池为修复"神经臂抹除真实小暗点"（ACL-063）新增了密集小点缺陷族（hole 半径 1-4px、每景 20-50 个、部分深度 0.3-1.0、软边 1px），结果点保真度反向崩溃：孤立点 erased% 4.7%→~43%（ALL retention 0.60→0.33）。ACL-067 的 batch/patch 对齐对照实验已把病根**锁定在 v7 池的缺陷分布设计本身**，训练超参排除。owner 直接诉求：**验证成本太高——不能每次生成完 5000 景、训完 30k 步才发现数据有问题**。

## 修复思路：把验证从"训练后"搬到"训练前"——三层验证阶梯

任何新池配置必须逐层过关，成本每层递增约一个量级：

| 层 | 工具 | 成本 | 问的问题 |
|---|---|---|---|
| L1 可探测性审计 | `scripts/audit_defect_detectability.py`（新，零训练） | 分钟级 | 注入的缺陷在含噪 LR 输入端是否物理可恢复？ |
| L2 微型训练探针 | 300 景池 + 8k 步 + `probe_dot_retention.py`（3562 真实点集） | ~1.5h/臂 | 网络在这个池上会不会学出抹除先验？ |
| L3 生产验证 | 5000 景 + 30k 步 + 三轴复评 | ~10h | 最终确认（只有 L1+L2 全过才允许进入） |

**L1 的机制假设**（本轮要检验的核心）：v7 小点在 2× SR 的 LR 输入里只有 0.5-2px、深度低到 0.3、软边、叠 PSF 和结构化噪声——很可能大比例低于探测阈值。训练目标含不可恢复内容时，贝叶斯最优输出=先验均值（抹平），网络于是**学会**抹除小暗点并泛化到真实域。v6 的洞（4-13px、全深、硬边、每景≤6）在输入端不可能漏，所以 v6 网络从未学过这个抹除先验（ACL-066 的"没见过 vs 学会抹"猜想）。审计对每个 recorded hole 实例算两种 CNR（解析匹配滤波 + 经验局部测量），按半径×深度分层。

**L2 的仪器标定纪律**：先用已知答案标定仪器——v6-recipe 端点 vs v7-recipe 端点两个 300 景微型池、完全相同的 depb9v6 配方（b8/p384/seed42，旗标从 v24 checkpoint 保存的 config 逐项重建，非文字复原——ACL-067 教训）短训 8k 步。**只有微型端点复现出已知缺口的方向（v7 erased% ≥ 3× v6）仪器才算成立**，然后才跑消融梯。8k 不够就在 4k/8k 两个 checkpoint 上都测，仍不够则加步数减臂数。

**L2 消融梯**（单变量纪律，全部以 v7_cpu 为基、同 seed 20260902 使非缺陷内容与 v7 池头部逐景配对）：

| 臂 | 回退项 | 配置 |
|---|---|---|
| density | min_holes 20→0, max_holes 50→6 | `pool_2x_v7ab_density300.json` |
| radius | hole_radius_px [1,4]→[4,13] | `pool_2x_v7ab_radius300.json` |
| depth | hole_depth_range [0.3,1.0]→[1.0,1.0] | `pool_2x_v7ab_depth300.json` |
| edge | hole_edge_softness_px 1.0→0.0 | `pool_2x_v7ab_edge300.json` |

L1 审计结果决定训练优先级（GPU 串行，未必全训）。

**标定第一轮结果（2026-07-09 01:30 远端，重要中间发现）**：8k 步端点标定**未通过**——sanity 臂（历史 depb9v6 30k checkpoint）精确复现 0.5984/4.66%（仪器本身无误），但 micro_v7end/micro_v6end 两端点（含各自 4k checkpoint）全部 isolated erased%=0.00、ALL retention 0.89-1.05：8k 步模型仍在"透传输入"阶段，**抹除先验尚未形成**。这本身是机制信息：点抹除是训练成熟度的涌现行为（8k 无 → 30k 时 v7 池 40%），不是从头就有的。按预注册规则改用"出现视界"设计：v7 端点 resume 至 24k（每 4k 存档），用 12k/16k/20k/24k 四点探针找抹除先验出现的最早步数 H，消融臂训到 H 再比。

**预注册判定规则**：
- 标定成立：v7 端点 erased% / v6 端点 erased% ≥ 3。
- 某臂"解救"：其 erased% 关闭端点缺口的 ≥70%；30-70% 记为共同因素；<30% 排除。
- v8 组装：保留 v7 的 composer/噪声升级和小点缺陷族**本身**，但把解救参数回退，并要求小点族整体落在 L1 可探测区域内（radius×depth 联合分布按审计结果裁剪）——建池初衷（教会网络保留小点）只有在"点可恢复"的前提下才成立。
- v8 生产池开跑前置条件（**pool acceptance gate，今后所有新池适用**）：
  1. 24 景 pilot 过 `scripts/audit_v7_tcforge_gates.py` ≥7/8；
  2. pilot 过 L1 可探测性审计（阈值以 v6 bench48 分布为参照）；
  3. 300 景微型池 + 8k 步微型探针 erased% ≤ 2× v6 端点；
  4. 配置里不允许存在标注"待标定/占位"的参数（v7 事故的直接流程根因：`hole_edge_fraction`/`hole_depth_range` 明写着"待 pilot 标定"却直接进了 5000 景生产）。
